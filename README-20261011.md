# 2026-10-11 实际改动与未完成事项

## B站

自写底栏脚本只处理 `/x/resource/show/tab` 和 `/x/resource/show/tab/v2`。公开 [Biliverse Enhanced导航数据](https://github.com/Biliverse/Enhanced/blob/main/src/function/database.mjs) 有 `data.bottom`、`tab_id=publish`、`bilibili://uper/center_plus`，所以可识别中间发布入口，不必猜 `show_plus` 字段。会员购按对应名称/URI/ID识别。其他入口、账号、会员信息和页面区域保留。

视频下方广告仍未确认修复。最新正式 [ADBlock v0.7.3](https://github.com/Biliverse/ADBlock/releases/tag/v0.7.3) 已处理 View/AIRelateAsync 等路径。已检查仓库本地重写和3份原有远程重写：212个代表请求未发现相互竞争的响应规则。用户手机自行增加的规则不在此检查范围。

新版响应脚本只新增已知视频接口命中日志，原广告处理保持不变，原始URL诊断缩减为主机和路径。新增日志没有请求参数、正文或身份数据。`format=missing/other/application/octet-stream` 可以帮助发现内容类型没有进入原处理分支；在没有实际响应前，不随意把未知字节当作已知protobuf改写。

B站导航脚本29项模拟测试、原响应逻辑及新增诊断13项模拟测试通过。没有在用户iPhone运行验证。刷新应用综合重写后要让App重新获取导航；看到日志中的实际处理数量才知道对应请求是否被处理。

## 抖音、微信、支付宝

# 微信／抖音／支付宝界面与权益核查（2026-10-11）

## 可交付候选

已编写一个独立的圈 X **抖音旧接口信息流去广告实验**，文件：

- `qx-rewrite-douyin-experimental.conf`
- `qx-douyin-feed-experimental.js`
- `douyin-fixture-results.json`：19/19 有意义的模拟响应与隔离测试通过；无 iPhone 实测。

该实验只对 `api*.amemv.com` / `aweme.snssdk.com` 的 `/aweme/v1/` 或 `/aweme/v2/` 下 `feed/`、`follow/feed/`、`nearby/feed/` 生效。只删除 `aweme_list` 或 `data[].aweme` 中 `is_ads === true`、或具有非空 `raw_ad_data` 的记录，保留普通视频、直播、游标、未知字段。日志仅含命中与计数，不输出完整 URL、查询参数、响应或身份数据。

**它不是抖音“＋”隐藏规则、不是权益卡激活规则，也不能据此说最新版抖音已适配。**

推荐主配置若添加，则作为单独的实验资源，不并入常用综合重写。用户明确授权实验，但老接口的 MitM 在新版可能导致无法加载；一旦出现这种现象，关闭该实验资源即可回退。无脚本日志只能说明未见脚本执行，不能单凭这一现象认定广告已经去除。命中日志出现但检查 0 项意味着响应结构不同；移除 0 项也不等于本次响应内没有其它形态广告。

## 实验依据和来源边界

1. [iEwha/Profiles 的 Aweme.sgmodule](https://github.com/iEwha/Profiles/blob/master/Surge/Aweme.sgmodule) 当前返回 HTTP 200，明确标注适用抖音 `<= 16.2.0`。配置和配套脚本是直接核查过的公开源码；该仓库 README 自述为搬运、不维护，不能当成 2026 年新适配。
2. [配套 Aweme.js](https://github.com/iEwha/Profiles/blob/master/Script/Aweme.js) 直接显示 `aweme_list[].raw_ad_data` 及 `data[].aweme` 结构。该文件最近提交 `be6af858224a1e014e4bf86e839881fbceae24dd`，日期 `2023-08-02T01:33:33Z`。源码还修改下载、审核状态并过滤直播；本实验未沿用这些副作用。
3. [irenemsIrenes/profiles 的 douyin.js](https://github.com/irenemsIrenes/profiles/blob/master/Quantumult/X/js/douyin.js) 直接显示 `aweme_list[].is_ads` 字段，配套 [sngxmini 的 douyin.conf](https://github.com/sngxmini/QuanX/blob/main/rewrite/douyin.conf) 同样明确旧版本限制。其个人关键词过滤与下载能力不在本实验内。
4. 旧原作者 `https://Choler.github.io/Surge/Script/Aweme.js` 与 `https://raw.githubusercontent.com/NobyDa/Script/master/Surge/JS/Aweme.js` 本次均返回 404。没有把这些失效 URL 加入新资源。
5. [fmz200 当前维护说明](https://github.com/fmz200/wool_scripts/blob/main/QuantumultX/rewrite/00-How-To-Use-Rewrite.md) 说明响应修改依赖可 MitM，并以抖音为障碍示例。这是维护者的实践说明，不能扩大为任何抖音域名永久不可处理的定理。

脚本是根据公开接口字段重新编写的短小清理器，没有复制旧脚本完整实现。下载的原文件、SHA-256、完整仓库目录检查在同目录 `sources-*.json` 与 `*-tree.json`。

## 为什么 B 站能改，不代表另外两个应用一行替换就能改

| 目标 | 本轮已知证据 | 结论 |
|---|---|---|
| B 站底栏 | 现有 Biliverse 与之前的 tab 实现有明确 `/x/resource/show/tab` 响应、`data.bottom`、`tab_id` / `uri` 及中间按钮字段；由 B 站专门 agent 处理 | 有可识别字段才可写窄范围修改；并不意味着全部 B 站功能都可改 |
| 抖音底部“＋” | 找到的圈 X 旧净化脚本只改 feed 广告和视频下载信息，没有导航 tab 接口/字段；公开原生界面改造项目采用进程内 Hook | 不是断言不可能，缺少当前 iOS 可解密的导航响应及隐藏字段，不能把任意 `show_plus=false` 伪装成已有依据 |
| 支付宝主界面 | [墨鱼 CainiaoAds.conf](https://github.com/ddgksf2013/Rewrite/blob/master/AdBlock/CainiaoAds.conf) 可核实的是菜鸟小程序的 `mtop.cainiao...` 接口；不是支付宝主首页 | 没找到主首页真实响应 schema，不将支付宝域名整体拦截，也不把菜鸟净化算作支付宝主页已完成 |

对抖音底栏的补充证据：[iOS DouyinLiquidGlass](https://github.com/jie0514lu-tech/DouyinLiquidGlass) 明确采用 Objective-C runtime 的进程内修改，并通过 dylib 注入运行；这类机制不等于 Quantumult X 网络重写。[抖柚 Android 模块](https://modules.lsposed.org/module/io.github.twyora.douyinenhancer/) 的移除底栏能力也依赖 Xposed，不能拿其功能表证明 iOS 圈 X 可用。

支付宝官方 [mPaaS 数据加密文档](https://help.aliyun.com/zh/document_detail/72752.html) 描述可选的 RPC 数据加密。它有助于理解“解开 HTTPS 后不一定是可改 JSON”，但**不是当前支付宝首页开启哪种加密的抓包证据**，不能用它断言首页必定不可改。

## 微信未成年模式与搜索

没有找到可独立设置这两个行为的当前 iOS 网络字段。直接检查 `ddgksf2013/Rewrite`、`fmz200/wool_scripts`、`deezertidal/QuantumultX-Rewrite`、`NobyDa/Script`、`Keywos/rule`、`chxm1023/Rewrite` 当前完整仓库树，微信相关代码是具体小程序、公众号、跳转或分流；未见青年模式与全量搜索的拆分实现。

[墨鱼 WeChat.conf](https://github.com/ddgksf2013/Rewrite/blob/master/AdBlock/WeChat.conf) 作者已标注公众号旧接口失效，并提及开启实际青少年模式；不含“伪装未成年但恢复搜索”脚本。[fmz200 WeChatMiniAds.plugin](https://github.com/fmz200/wool_scripts/blob/main/Loon/plugin/WeChatMiniAds.plugin) 是具体小程序域名和请求规则，不设置微信模式状态。Keywos `mocks/WeChat.json` 仅为 `advertisement_num` / `advertisement_info` 空广告响应，也不是模式开关。

本次没有生成虚构模式规则。后续若要开发，需要用户 iPhone 中实际触发的脱敏接口结构，或可核实的原始实现；不能从一张界面图推导出请求协议。若模式本身决定不发出搜索请求，仅修改服务器响应也不会凭空恢复客户端入口。

## 当前配置事实

当前重写的 X 处理只匹配 x.com 网页，MITM 最后新增的是 x.com，没有加入 api.x.com 或 api.twitter.com；所以用户说官方 App 仍有广告符合规则覆盖范围。多源 DNS 里包含 p.twitter.com、scribe.twitter.com、urls.api.twitter.com 等广告/统计域名，但拦截它们不能保证消除混在时间线的推广帖。不能整站拒绝 X 主要内容 API，否则普通推文也可能断流。

## 为什么没有制作实验版

用户接受“未经验证”不等于可以凭空写接口。已有源码能证明网页 JSON 广告字段，也能证明原生注入去广告方法；缺的是“用户官方 iOS App 的具体响应可由 QX 解密，并包含这些字段”。直接扩大 MITM 到整个原生 API 有联网失败可能，且无真实样本证明收益。未把这个可能性说成用户手机已发生证书锁定；用户当前是否可解密尚不确定。

## 最小后续数据

在 iPhone 圈 X 的活动记录中复现 X 首页广告，仅需提供涉及 X 的域名、路径、请求类型、状态或 TLS/MitM 错误；不要公开 Cookie、Authorization、密码或令牌。若能解密得到对应 JSON，先脱敏再据实际结构写局部过滤，并验证普通推文、图片、游标和评论保留；若只能看到连接握手失败，则改 JSON 脚本也不会执行。当前已知源码不足以宣称能修好官方 X App。

证据树、源码快照、提交时间保存在本目录；这次未做 iPhone 实测。
